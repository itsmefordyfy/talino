# Building AI Agents: design (2026-11-18)

Owner's brief (pasted 2026-11-18): a complete project-based course "Building AI Agents" inside the existing Talino app: 12 modules with the listed lessons, a 30-question four-choice final assessment, practical
projects, a capstone with an architecture-design alternative, code that is accurate against current official SDK documentation, ten architecture diagrams, interactive exercises, differentiation from the existing AI courses,
integration with the existing course architecture, and a QA pass; then (mid-session) **"use kokoro tts here"**. The owner's standing rule is to make routine decisions independently; brainstorming gate: opted out, so this records the decisions.

## Intent
Learners move from *using* AI tools to *building* AI-powered applications. The course is code-first and honest about cost, failure and risk; the baseline is the simplest thing that works (one call before a loop, a workflow before a free-running agent, one agent before several, your own loop before a framework).

## Decisions (mine, recorded; the owner can overrule any)
1. **Course id `building-ai-agents`**, `kind: 'standard'`, level `intermediate`, category `advanced-ai-engineering`, goal `learn-ai-dev` only (adding `become-developer` would shift recommendation tests, as the architecture course found), prerequisites `how-llms-work` and `programming-fundamentals` (advice only), `volatile: true` (SDKs and frameworks move: at least 60% of lessons carry a dated, officially sourced `version` note).
2. **109 lessons, the owner's titles exactly** (101 teaching lessons in modules 1 to 11, then module 12: a review, six assessment parts, the capstone guide), **8 projects** (after days 24, 33, 42, 52, 62, 72, 89, 109). Lesson minutes follow the app's 10-minute minimum, so the course is about 30 hours by `minutes`, against the brief's 8 to 12: recorded, not trimmed (the same call as the LLM and AI Automation courses). `MODULE_COURSE_MAX_LESSONS` rises 90 to 120.
3. **The final assessment is the quizzes of lessons 103 to 108: six parts of five questions, 30 in all, four choices, an explanation each; four shared + three level-band questions per part, so every learner level answers exactly five per part** (pattern of `how-llms-work`). The 60% pass rule, best-attempt storage and XP are the app's, unchanged.
4. **No new engine and no live model call.** Interactivity reuses what exists: runnable JavaScript `code-challenge`, `fix-bug` and `predict-output` activities (the in-app interpreter has no network or async, so agent logic is taught against **scripted stand-ins for the model**, labelled as such), `workflow-builder`, `scenario`, `match`, `arrange`, `tap-reveal`, the `ai-agent-loop`, `ai-rag`, `ai-context-window`, `ai-embeddings` visuals, and the architecture course's `arch-diagram-workbench` and `arch-adr-builder`. No `prompt-lab` (would add live Gemini cost and a server dependency).
5. **Code is shown in Python (default), TypeScript, SQL and shell** as copyable `code` blocks (the app does not run them). Accuracy rule: every SDK call, parameter, package and model id comes from two verified fact sheets (`docs/content/AGENTS_FACTS_A.md` providers, embeddings, pgvector, Supabase; `AGENTS_FACTS_B.md` frameworks, SDKs, MCP, security) built from official pages read on 2026-11-18; pure-logic samples are run on this Mac and their output pasted; samples that need a key are syntax-checked only and labelled "the shape".
6. **A no-key path:** project builds offer a `ScriptedModel` so learners without a paid API can still run the loop, tools, validation and limits. The capstone has an architecture-design alternative graded by the same rubric.
7. **Tali** gets course-wide agent-builder instructions (`coach/lib/ai-agents.ts`: hints before solutions, never writes the learner's agent, never asks for or accepts keys, treats pasted logs and traces as untrusted, refuses to design unbounded or unapproved-action agents, recommendations are hypotheses). No new focus kind, no new route.
8. **Overlap:** `agentic-coding` and `multi-agent-dev` teach *using* coding agents and stay unchanged; `how-llms-work` module 10 explains tool calling as an idea and this course builds it; `ai-automation-business` module 7 is no-code agents. Recorded as `OVERLAPS.md` entry 16. The later *Advanced AI Agent Development* course is not built.
9. **Placement:** world "The Agent Workshop", cover `smart_toy` icon, a side late-addition journey milestone, added to learning paths by id (`agentic-engineer`), What's New item.
10. **Narration is Kokoro only** (owner, 2026-11-18, and the standing rule): lesson scripts exported with `scripts/audio`, `run-building-ai-agents.sh` written and started; recordings are not uploaded (the owner hosts them with `upload-r2.mjs`). Gemini speech is never used.
11. **English only.** New strings are English; where a typed table needs `fil`, English is a placeholder listed as pending.

## Honesty rules (structural)
No price, rate limit, quota, benchmark, ranking or popularity figure; no claim about a named product's internals; product facts only in dated, official-source version notes; AI demos are labelled hand-written illustrations; security content is defensive; agents never get unrestricted access to sensitive systems; frameworks are described by what they are for, never ranked.

## Tests and verification
Per-module authoring check (`catalog/agents-module.test.ts`, `CHECK_AGENTS_MODULE=n`), whole-course check and learner journey (`building-ai-agents.course.test.ts`: 12 modules, 109 lessons, 30 assessment questions at every level, scoring, completion), `CHECK_COURSE`, tsc, eslint, catalog and recommendation suites, Android bundle export. What cannot be verified here (no screen was seen, no live call was made, no expert reviewed the content) is listed in `docs/content/AGENTS_STATUS.md`.
