# Talino AI 1.0: design

Date: 2026-11-13. Source: the business plan (https://claude.ai/artifact/9U4ZSnmb6thBzPuMjo2u6g,
`documents/Talino AI — Business Plan.pdf`). The owner asked for **every feature in the plan** and
handed every decision to Claude ("I will let you handle best decision, do not ask me"). Everything
marked *Claude's call* below is open to the owner's correction.

## Intent

A phone app that coaches tech people to thrive with AI: a free starter course, career courses bought
one at a time, daily 15-minute lessons with quizzes and laptop tasks, coach-reviewed projects, badges
and streaks, a certificate that means something, a career tracker, a résumé and a public portfolio
built from what was done, and Tali, the AI coach (freelancing and AI engineering specialties plus a
role per course).

**Goals:** a learner can install, take the starter course end to end, buy a course, finish it with
reviewed projects and get a verifiable certificate; track their job or client hunt; export a résumé;
publish a portfolio. Schools and employers have a working, minimal path (class codes, talent list).

**Non-goals (the plan's "what it is not"):** no code editor or app builder on the phone, no general
chatbot, no job or income promise.

**Anti-goals:** a certificate anyone can fake by tapping through; secrets or the Gemini key in the
app bundle; paid AI calls that run without a cap; lessons that state unverified facts as current.

## Approaches considered

1. **Port Bubblie's foundation and features (chosen).** Bubblie is on the same SDK 58 / RN 0.88 and
   has the design system components, SQLite + React Query plumbing, Redux persistence, RevenueCat
   with a simulated store, the AI chat with history and the server-side chat allowance. Fastest and
   keeps every Fordytech app built the same way.
2. Build from the playbook templates only: cleaner but weeks slower, and drifts from the other apps.
3. A web-first app (DOM components): wrong for a daily phone habit with notifications and purchases.

## Decisions (Claude's calls unless marked)

- **Brand:** indigo `#4F46E5` primary, violet `#7C3AED` accent, amber `#FBBF24` spark (the plan's
  proposal). Inter (playbook default), system monospace for code. Material Symbols Rounded. Mascot
  **Tali the tarsier**, drawn as SVG in the app. Icon: amber spark in white code brackets on an
  indigo-to-violet tile, generated from SVG.
- **Language:** English at launch; strings sit in one file so Filipino can be added.
- **Tabs (5):** Today (the daily path, streak, next lesson), Courses (catalog and owned courses),
  Tali (coach chat), Career (tracker, résumé, portfolio, templates), Me (progress, badges,
  certificates; Settings from its header).
- **Data:** SQLite on the phone is the source of truth (progress, projects, badges, streak days,
  certificates, career tracker, income, goals, résumé, chats). Redux (persisted to the kv store) for
  settings and onboarding. React Query reads. Append-only migrations from the first build.
- **Content:** bundled TypeScript data, one file per course (`features/courses/content`), validated
  by a test. Server patches later through `/api/content` (the plan's stale-content fallback).
  All 6 courses' lessons and 6 mini-courses were drafted by Claude on 2026-11-13 and **need the
  senior-developer review the plan budgets for** before launch.
- **Catalog:** starter (free, 7 lessons, 1 project, certificate); Developer, Freelancer & VA,
  Builder, Experienced Developer, Educator (20 lessons each, 2–3 projects, certificate, a coach
  role); 6 mini-courses (5 lessons, 1 project, a badge). Talino Master certificate for all five
  career courses.
- **Selling:** RevenueCat. Each course is a non-consumable product; the "any 3 courses" deal is the
  **Career bundle: the three launch courses** (Developer, Freelancer & VA, Builder) as one product,
  because "any 3" would need picks recorded on a server and at launch there are exactly three. One
  entitlement per course (`course_<id>`) is attached to its own product, the bundle (launch three)
  and the All-Access subscriptions; `all_access` is attached to the subscriptions. The app only reads
  entitlements. A development build with no key uses a simulated store.
- **Coach:** an Expo API route (`/api/coach`) calling Gemini Flash, ported from Bubblie/CarMind.
  Allowance per the plan: Free 3 new chats per rolling 24 h; anyone who owns a course or All-Access
  gets fair use (100 per 24 h). Counted on the server (`ai_chats` table in the shared Supabase
  project, `app = 'talino'`; in-memory in development). Course roles (mock interviewer, code
  reviewer, proposal reviewer, lesson planner, build buddy) need that course or All-Access; the
  freelancing and AI engineering specialties are open to everyone.
- **Project reviews:** `/api/coach` `mode: 'review'` returns a pass/needs-work verdict with feedback.
  A pass carries an HMAC token (`REVIEW_SIGNING_SECRET`) over the project id and the app user id;
  reviews don't count as chats but have their own daily cap.
- **Certificates:** unlock only when every lesson and quiz is done and every project passed review.
  Issued by `/api/certificates`, which checks the review tokens and, for paid courses, the course
  entitlement through RevenueCat's REST API, and stores the record (Supabase
  `talino_certificates`). Public page `/c/<id>` (HTML from an API route) with name, course, date and
  projects. The app shows the certificate, makes a PDF with a QR code to that page and shares it.
  Offline or before the server is deployed, the certificate is earned in the app and can be
  verified later. Known limit: lesson and quiz completion are recorded on the phone and can't be
  proven to the server.
- **Résumé:** built from the profile, finished projects, certificates, badges and skills; three
  versions (developer job, freelance, AI engineer); an ATS-friendly single-column PDF (`expo-print`);
  the coach tailors the summary and bullets to a pasted job post (`mode: 'tailor'`, validated JSON).
- **Portfolio:** published to `/api/portfolio` (Supabase `talino_portfolios`), public page
  `/p/<slug>`, edited and removed with a secret token kept on the phone. **Talent list** opt-in on
  the same record.
- **Templates:** LinkedIn headline and About, Upwork/OnlineJobs proposal, cover letter, follow-up
  email, filled from the profile, with Copy.
- **Career tracker:** applications and proposals (saved, applied, interview, offer, hired/won,
  closed), follow-up and interview reminders (local notifications; the evening before an interview
  opens Tali's mock interview), freelance income per client, and goals with progress.
- **Progress:** course progress (lessons, quiz average, projects), a skills meter per course, a
  streak with a daily reminder at the learner's time, badges.
- **Lesson audio:** `expo-speech` reads the lesson aloud on the phone (no cost, works offline).
- **Starter quiz:** after the starter course, 5 questions recommend a career course.
- **Onboarding:** welcome, goal (the five audiences), name, reminder time, then the first lesson.
- **Schools and companies:** a class code (`/api/classes`, Supabase `talino_classes`) grants the
  class's courses as RevenueCat promotional entitlements for the seat's term and shares the
  learner's progress with the class; the teacher reads a progress page `/teacher/<code>?key=…`.
  Codes are created in the Supabase SQL Editor (no admin dashboard in 1.0).
- **Employers:** `/talent?key=…` lists opted-in learners (certificates, portfolio link, contact
  email they chose), keys in `talino_employers`. Placement fees are handled outside the app.
- **Referrals:** Me → Invite friends shares a code; a friend enters it once; the server records it;
  the RevenueCat webhook (`/api/revenuecat-webhook`) grants the referrer a mini-course
  (promotional entitlement) after the friend's first purchase. The friend's discount needs store
  offer codes the owner creates; the app shows the "referral" offering when RevenueCat has one.
- **No sign-in.** Identity is RevenueCat's anonymous app user id plus a Keychain-backed device id;
  purchases come back with Restore. Backup of progress (iCloud / Google Drive, Bubblie's module)
  follows after 1.0's core.
- **Not in 1.0:** Sentry (needs the owner's DSN; the module is a no-op without it), analytics, ads,
  Apple Watch app, widgets, a web dashboard beyond the two key-protected pages.
