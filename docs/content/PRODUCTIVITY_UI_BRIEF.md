# Productivity tools: brief for UI builders (2026-11-17)

Course: Time Management and Productivity. Design: `docs/superpowers/specs/2026-11-17-productivity-course-design.md` (read it first, 5 minutes). The logic is **done and tested**; you build the screens that sit on it.

## What already exists (do not rewrite; import it)
`src/features/productivity/` (public API: `@/features/productivity`):

- Contract stubs you replace: `productivity/components/matrix-board.tsx` (`MatrixBoard`), `productivity/components/day-planner.tsx` (`DayPlanner`), `activities/components/planning-prioritize-panel.tsx`, `activities/components/planning-schedule-panel.tsx`, `visuals/productivity/{eisenhower,schedule,pomodoro,prompt-playground}-visual.tsx`. Keep every exported name and prop type (other code imports them); you may add props. `activities/components/planning-view.tsx` already chooses the panel by mode.

## Rules (the app's, from CLAUDE.md and the playbook; read them)
- Load and follow the `mobile-app-playbook` skill, `talino:platform-design`, and use `talino:ui-ux-pro-max` for layout and type choices. Tokens only from `constants/theme.ts` (no hardcoded colour, size or spacing), `ThemedText` / `Card` / `Button` / `Icon` / `Notice` / `ChipSelect` etc. from `components/ui` (check there before writing a primitive), Material Symbols names must exist in `components/ui/material-symbols.json`, `expo-image` for images, `StyleSheet.create`, `borderCurve: 'continuous'`, no `useMemo`/`useCallback`/`React.memo` (React Compiler is on), no `any`, kebab-case files, named exports with an exported `<Name>Props` type, `@/` imports.
- **No new dependency.** No drag-and-drop library: use tap-to-select and buttons (steppers in 15-minute steps), which also makes everything keyboard and screen-reader usable. Every control: `accessibilityRole`, `accessibilityLabel`, touch target at least 44 pt, `tapFeedback()` from `@/lib/haptics` on primary taps. State is never conveyed by colour alone (text or icon too). Respect Reduce Motion for any animation. Dynamic Type must not clip.
- Layout must work at iPhone width (about 390), iPad and web widths (use `useViewport`/the existing wide-layout helpers the other screens use; cap content width; a 2x2 matrix is fine at phone width if the titles are short), Android, light and dark mode.
- Every data-backed tool handles **loading, error (with retry), empty (with a next step) and content**; use the shared state views in `components/ui`. Local reads: `useDbQuery` / `useDbMutation` (see `db/`); keys of your own under `['productivity', ...]`. Debounce nothing fancy: a write per change is fine (small JSON).
- **Honesty:** the Prompt Playground and its check are rule-based and say so on screen ("Not an AI. A checklist."). A made-up output is never shown as an AI's. The timer says it does not send a notification. Do not claim anything the code does not do.
- Do not write Filipino. New words go in `productivity/strings.ts` inside your own section (clear comment header; **re-read the file before each edit, other builders edit it too, change only your section**). Components contain no literal interface text.
- Tests: pure helpers you add get a `*.test.ts` next to them (Jest, `@jest/globals`). For components, follow `activities/components/practice-view.test.tsx` or `workflow-builder-view.test.tsx` (react-test-renderer style) where it is cheap; test the behaviour that matters (adding, moving, persisting, the check result shown), not snapshots.
- You may edit only the files named in your task plus new files under `productivity/` (components, hooks) you create. **Do not run git.** The working tree has other agents' unfinished changes (Generative AI course: `practice/lib/lab-review.ts` type errors etc.); an error in a file you did not touch is not yours, but never leave an error in yours: run `npx tsc --noEmit` and `npx eslint <your files>`, and `npx jest --no-watchman <your tests>`.
- If you can, look at it running: Metro on 8081 with the iPhone 18 Pro simulator, Concept Lab (`/concept-lab`) lists the visuals; the simulator takes no taps here, so say plainly what you could not see.
- Report at the end: files changed, behaviour built, tests added and their results, what you saw, what you did not check.

## What good looks like
Real tools a learner would keep using: add their own tasks, see them move, come back later and find them there. The graded activity reuses the same board with the scenario's fixed tasks and shows, after Check, what was right and what to look at again, in words. A schedule that is overpacked is visibly overpacked (the day line shows work, rest, free time and conflicts) before the learner presses Check.
