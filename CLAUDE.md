# CLAUDE.md

Talino ("AI Career Coach for Tech"; called "Talino AI" until 2026-11-15): an iOS and Android app that coaches tech people to thrive
with AI, whether they want a developer job, freelance or VA work, to teach, or to build their own app
or website without being a programmer. Modelled on Josie AI (a VA career coach), widened to the whole
tech career. Bundle id / package `com.fordytechsolutions.talino`; version in `app.json`.

This app follows the owner's mobile app playbook (the `mobile-app-playbook` skill, installed for
every project at `~/.claude/skills/mobile-app-playbook/`). Load it at the start of any work here.
This file is the source of truth for this app: where it and the playbook differ, this file wins.

Business plan (the owner's and Claude's working doc, 2026-11-13):
https://claude.ai/artifact/9U4ZSnmb6thBzPuMjo2u6g. It holds the audiences, courses, features,
prices, projection and roadmap; decisions below are only what the owner has confirmed.

## Commands

```bash
npm run ios                 # dev build on the iPhone 18 Pro simulator, starts Metro
npm run android             # dev build on the Android emulator or a phone
npm run ios:prod | android:prod   # release-like local build
npm run ios:watch           # prebuild with the Apple Watch targets (TALINO_WATCH=1), then the iPhone dev build
npm run prebuild:ios|prebuild:android   # regenerate ios/ or android/ after a native config change
npx expo start              # Metro only, once a dev build is installed
npx expo lint               # lint
npx tsc --noEmit            # typecheck
npm run check               # lint + typecheck (add tests once Jest is set up)
npx expo-doctor             # dependency / config diagnostics
npx expo install <pkg>      # ALWAYS use to add packages
npm run release:ios         # TestFlight upload, phone app only (-- minor / -- major)
npm run release:ios:watch   # the same with the Apple Watch app
npm run release:android     # signed .aab for Play Console (release:android:apk adds an APK)
```

- **Git:** commit only when the owner asks, or when they've chosen a Superpowers execution mode that

## Architecture

- **Routes** (`src/app/`): Expo Router; route files stay thin, default-export, and compose
  `src/features/` and `src/components/`.
- **Features** (`src/features/<name>/`): `index.ts` is the public API; other features import only
  from it. Code used by 2+ features moves to `src/components/`, `src/hooks/` or `src/lib/`.
- **Components**, each layer importing only from below: `src/components/ui/` (primitives, data
  through props, no store/DB access) → `src/components/` (shared composites) →
  `src/features/<name>/components/`. Check `ui/` before writing UI.
- **Constants** (`src/constants/`): `theme.ts` holds every color, spacing and type token (light and
  dark); strings in one strings file, no literal interface text in components.
- **Server code** (when needed): Expo Router API routes (`src/app/api/*+api.ts`) are the only server
  code. They can't import native modules; shared prompt or validation logic lives in a feature file
  both sides import.
- **Native:** `ios/` and `android/` are generated (CNG, gitignored), never hand-edited. Native changes
  go through `app.json`, `app.config.js` and config plugins in `plugins/`.
- **Data:** decided when the first feature needs it (see Open questions); the playbook's
  offline-first rules apply (append-only migrations, ids made on the phone, deletes with dependents).

## Conventions

- TypeScript strict; no `any` (use `unknown` and narrow). Functional components only.
- kebab-case file names; PascalCase components with named exports and an exported `<Name>Props`
  type; route files default-export. `@/` imports.
- **No Prettier or other formatter.** Don't run one; match surrounding style.
- Comments explain *why* (platform bug, data rule), not *what*.
- React Compiler memoizes: no `useMemo` / `useCallback` / `React.memo` unless it bails out or a
  non-compiled consumer needs a stable reference.
- `expo-image`, not `Image`. `FlatList` / FlashList for long lists. `react-native-safe-area-context`,
  not RN's `SafeAreaView`.
- Pressables set `accessibilityRole` and `accessibilityLabel`; touch targets ≥ 44pt. Light haptic on
  primary taps through one `tapFeedback()` helper. Respect Reduce Motion for decorative animation.
- Don't add a dependency when an Expo module or a few lines of code will do; check with the owner
  before adding anything large. Always `npx expo install`.

## Error handling

- Every data screen handles **loading, error, empty (with a next-step button) and content**, through
  shared state views in `ui/` (the spinner waits about 400 ms so fast local reads don't flash).
- Never swallow an error silently: show a calm message with a retry, or carry on and report it.

## Security

- Secrets live in gitignored `.env*` files. Only `EXPO_PUBLIC_*` values reach the client, and they
  are public: never put an API key there. Server secrets are read only in `+api.ts` routes.
- **Paid API keys are the owner's.** Ask before using any key for something new.
- Anything a model or server returns is untrusted: validate its shape before acting on it.
- Ask for a permission at the moment it's needed, with a reason, and handle "denied" gracefully.
